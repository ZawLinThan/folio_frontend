# Folio workspace

Folio is a study SaaS for turning existing course materials into answers and practice. The interface should make the next study action clear wherever the user enters.

- **Navigation:** The public root introduces Folio and routes to sign-in and sign-up. The same URL opens Overview for people with a session. Overview gives orientation. Library contains courses and documents. Study tools contains assistant, flashcards, tests, and focus timer. Settings sits with account identity. At narrow widths, use one labeled disclosure that exposes the same destinations.
- **Hierarchy:** Use a single clear page title, a short description, and one visually dominant action per surface. Overview leads with the assistant; labeled metrics are shortcuts to their respective collections. Empty collections direct users to where they can add content.
- **Color:** The public landing page uses warm paper (#FAF9F6), charcoal ink (#18181B), and forest green (#15803D). The workspace carries the same palette in light mode and uses a muted charcoal and sage palette in dark mode. Use green for actions, focus, and source references.
- **Type and geometry:** Use Georgia for display headings, Geist for interface text, and JetBrains Mono for source badges and editorial labels. Use tabular figures for counts and time. Keep consistent 8–12 px spacing within groups and larger gaps between sections. Use Lucide icons with text where possible.
- **Text fields:** A composite field, such as a search bar or chat composer, has one border on its outer frame. Keep the embedded input or textarea borderless and show focus on the frame. Standalone fields and action buttons retain their own focus indicators.
- **States:** Use the same visible heading, navigation, grid, and control footprints for loading and loaded views. Skeleton controls are inert. Keep visible keyboard focus, predictable reading order, and motion optional.
